2. **B / P0 탐지**: 자체 Python·JS/TS·템플릿 규칙, 시크릿 탐지/마스킹 공통화, 민감 파일 메타데이터, 설정 검사, Flask/FastAPI/Express 라우트와 인증·인가 후보. 검증: 각 규칙 취약/안전 표본, 비밀값 출력·전송 방지, 가드가 있는 안전 라우트, 35개 패턴 재구성 벤치마크. 목표: 28/35 이상, P0 재현율 0.8·정밀도 0.7 이상.
3. **C / 결과 연결**: 21개 CI 및 4개 V 항목의 점검 상태를 계산해 결과 JSON과 검사 범위 판정에 사용. KISA 점검표·CI 코드·엔드포인트 지도·설정 요약은 사용자 요청에 따라 보고서와 대시보드에 표시하지 않음(내부 전용). 검증: 구버전 결과·설치된 패키지·전체 회귀.

**후속 D**: 카탈로그 전체 모델 계획, 인가 전용 검토, JS/TS 안전 발췌, 트리아지 캐시, 실계정 완주. 이번에는 기존 모델 검토를 유지하며 확장 발견이 검토 실패로 사라지지 않도록 한다.

**후속 E/P2**: SCA(OSV opt-in), BaaS 정책, Django/Next.js 라우트, 프론트/API 가드 대조, 추가 CSRF/자동화 규칙, 점수 공식 변경, Git 이력·동적 검사. 해당 항목은 자동 점검 완료로 표시하지 않는다.

판정 원칙: 정적 후보이며 KISA 공식 평가가 아니다. 가드나 소유자 조건을 찾지 못한 것은 우회가 확인됐다는 뜻이 아니다. 함수·파일 간 흐름, 배포 설정은 수동 확인 대상으로 남긴다. 원본 시크릿을 결과·SQLite·모델 요청에 남기지 않는다.

## 구현 결과 및 조정

- 작업 브랜치: `feat/diagnosis-hardening` (`feat/local-dashboard`의 `d7b68f1`에서 분기). 진단 결과를 표시하는 UI 연동도 같은 변경에 포함한다.
- A: 하드코딩 CWE 분기 제거, 메타데이터 규칙, 정규화·지문·중복 제거, 부분 파일 오류, JSON 기본값·SQLite 추가 열 구현. **원문 대조는 미완료**: 공식 첨부 PDF를 내려받고 목차·텍스트를 확인했으나 CI 체계를 확인하지 못했다. 카탈로그를 명시적인 초안으로 제공하며 공식 중요도·페이지는 만들지 않는다.
- B: 자체 규칙 20개와 시크릿/설정/라우트 검사 구현. 35개 프로브는 원본 레포가 제공되지 않아 문서의 패턴을 재구성했다. 결과는 `bench/report.md`에 기록한다. 각 규칙에 안전 표본 포함.
- C: 25개 분류와 6상태, 보고서, 코드 필터·점검표·라우트·설정 UI 구현. 미지원 언어/프레임워크·부분 실패를 미발견과 구분한다. 구버전 결과는 검사 여부 미확인으로 표시한다.
- 보수적으로 조정: 관리자 가드 미확인도 Potential이다. 단순 라우트 패턴으로 인증 우회가 확인됐다고 주장하지 않는다. 여러 탐지기의 동일 패턴 일치만으로 확신도를 올리지 않는다. 파일 종류만으로 민감 파일을 보고하므로 실제 값 없는 커밋 파일도 후보가 될 수 있다.
- 최소 구현의 한계: Express는 같은 파일의 리터럴 핸들러만, Python 라우트 접두어는 리터럴만 추적한다. 상위 라우터·전역 훅은 확인 필요로 남긴다. JS 함수 경계는 휴리스틱이다. `.gitignore` 누락 예방 권고, 일반 엔트로피 기반 추가 탐지, 모든 프레임워크 설정 요약, JS 지문의 내부 공백 정규화, taint 경로 UI는 후속 보강으로 남긴다.
- 로컬 검증 완료: Python 64개 중 63개 통과, Windows 심볼릭 링크 권한으로 1개 건너뜀. Semgrep 규칙 20개 취약/안전 테스트 통과. 기준표 34/35 탐지·안전 0/22 오탐. Node UI 회귀 및 설치된 CLI/웹 자산의 저장소 밖 실행 통과. 실제 브라우저에서 25개 카드, CI-02 필터 5건, 상세의 마스킹된 근거, 390px 가로 넘침 없음·콘솔 오류 없음 확인.
- 미검증: 원격 GitHub Actions, 실계정 모델 호출, 외부 취약앱 일반화. 실서비스 정확도를 합성 표본 수치로 주장하지 않는다.
